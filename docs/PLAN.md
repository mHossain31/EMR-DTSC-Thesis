# Plan: rebuild the SUMO + ML NYC emissions study (docs/SPECIFICATION.md, sections 1-12)

## Context

The 2024 DTSC 870 project (Hossain and Kyaw, supervised by Prof. X. Huang) reported 64-74% emission reductions from
ML-triggered rerouting in a SUMO model of Flushing. The study specification calls for a
research-grade rebuild: an audit of the legacy work, three ready-to-run NYC SUMO scenarios, and a preregistered, paired,
multi-seed experiment on forecast-driven eco-routing with proper baselines and placebos. Also wanted: a paper and
application materials generated from results, ready in time for the Dec 15 deadline (interim note usable
for Dec 1). The specification governs the study; this plan covers how it gets executed on this machine, in what order,
and what the inspection has already shown.

### What the legacy files already show (read-only inspection, Nov 14)
All three legacy files were taken from a local Downloads folder (report 48 pp., slides 31 pp., zip with the 34 MB
notebook) and copied to `legacy/`. Details: `docs/LEGACY_AUDIT.md` (generated).
- **D1, unmatched horizon: strongly supported.** The baseline `emissions_data.xml` has 642,472 vehicle-step rows. Its
  normalized Time column puts 1 s at 0.000242, so the run spans about 4,130 s. Both controlled runs stop at step 1000.
  Their in-run logs hold 195,640 rows (RF) and 174,518 rows (XGB): 30.5% and 27.2% of the baseline. Row count alone
  therefore gives "drops" of about 69.5% and 72.8%, the same size as the reported 64-74%. Final confirmation comes from
  the replication in M4, because the emission XMLs themselves are gone.
- **D2, no-op reroutes: strongly supported.** The RF run made 38,810 reroute calls across 832 vehicles, and the XGB run
  41,323 across 829. Every repeat call (37,978 and 40,494) returned the vehicle's unchanged remaining route. The first
  call per vehicle cannot be checked, because the old route was never logged. The two controlled runs still diverge
  (different row counts), so `setRoute` was not behaviour-neutral, or a setting differed. The M4 replication
  investigates this.
- **D4, circular and leaky task: confirmed.** The models use the raw `df`; `normalized_df` is never used after cell 12.
  The reported RF MSE of 0.000105 is the 6-feature model with X and Y (cell 18). The RF actually deployed for
  rerouting is the 4-feature model, MSE 0.000206 (cell 30), which the report never gives. Splits are random by row.
- **D6, threshold units: confirmed.** 1.88 is labelled "bpm" (cell 32), "ppm" (cell 46) and "g/mile" (report pp. 15-16,
  slides p. 17). It is compared against predicted SUMO emission-output NOx, a per-vehicle rate (mg/s; to verify on the
  installed SUMO).
- **D5, "multiple runs averaged" (report p. 30): no evidence.** The notebook has one baseline file and one run per model.
- **D7, hard-coded stand-in values: confirmed.**
  - Cells 24 and 26 hard-code MSEs with comments asking for the actual values to be filled in. Cell 57 invents drops
    of 15 and 25 and NOx values.
  - Every path is a hard-coded absolute path on drive D.
  - Cell 2 has no `step += 1`; its saved output shows Step 0 for successive positions of veh0.
  - Slides p. 25 still carries template text ("98,300,000 Big numbers catch your audience's attention").
  - The report's row count (638,367) differs from the notebook's (642,472).
- **D8, references: to verify.** There are internal inconsistencies: "Dong & Javid et al. (2022)" in the slides
  against separate Dong 2021 and Javid 2022 entries in the report; volume and year pairs that look mismatched;
  "(MDPI)" and "(SpringerLink)" tags left in the text.

## Decisions and defaults
1. **Repo root = the project folder `EMR-DTSC-THESIS`.** It holds the layout of docs/SPECIFICATION.md 5.1; the folder is not renamed to
   `nyc-emissions-sumo`, and this is noted in `docs/DESIGN.md`. `git init` on `main`, one commit per gate
   (`M3: ...` messages), no remote, no push.
2. **Environment.**
   - `.venv` built with `uv venv --python 3.12` and `uv pip install`; `requirements.lock` is generated by
     `uv pip compile`, and README commands also work with plain pip.
   - SUMO comes from PyPI (`eclipse-sumo`, `libsumo`, `traci`, `sumolib`, latest stable at install time, pinned), so
     no system install and no admin rights.
3. **TeX.** The tectonic Windows binary (about 20 MB, GitHub releases) is downloaded into a gitignored `tools/`, at M9
   only. Tectonic then fetches its TeX bundle (about 100-300 MB) on first compile. If either step fails: `.tex` plus a
   Markdown rendering, recorded as environment-limited.
4. **Legacy files.**
   - The three files are copied to `legacy/` and committed (about 15 MB). The extracted 34 MB `.ipynb` is gitignored.
   - Committed extracts: `legacy/notebook_code.py` (outputs stripped), `legacy/notebook_outputs.txt` (the text outputs
     the audit cites) and the PDF text, page by page.
5. **Workers = 23 (cores - 1),** as the specification says. The PC will be slow while batches run; Fewer workers leave the machine more responsive.
6. **The specification already fixes the design.** The independent review that
   section 9.11 requires runs before G7.

## Execution, milestone by milestone (targets from docs/SPECIFICATION.md 10.1)

**M0 Preflight and audit (Nov 15).**
- Write `docs/SPECIFICATION.md`, `STATUS.md` and `docs/PLAN.md`
  (this plan), plus `NOTICE.md` with the OSM attribution, MIT `LICENSE` and `.gitignore`.
- Scaffold the 5.1 layout: `pyproject.toml` with the package `src/nycemis`, a typer CLI (`python -m nycemis ...`) and
  pydantic v2 configs.
- `env.py` handles SUMO discovery (`sumo.SUMO_HOME`), the libsumo/TraCI adapter with `preloadLibraries` on Windows,
  and version capture.
- `doctor` runs every 5.2 check, including Overpass reachability, and reports CARLA readiness for information only.
- Extract the legacy files. `legacy-audit` recomputes the numbers above from the zip, writes
  `docs/LEGACY_AUDIT.md` (claim, evidence, status, remedy) and verifies each legacy reference from primary sources
  into `docs/CITATION_LEDGER.md`.
- **G0:** doctor green, audit complete, plan committed.

**M1 Networks (Nov 16).**
- `osmGet.py` for the three bboxes in 6.3, with retries and mirror fallback; the extracts are frozen with SHA-256 in
  `data/MANIFEST.json`.
- Read the installed `osmWebWizard.py` and copy its netconvert options, typemaps and vehicle-class handling exactly,
  recorded in `network_build.json`.
- `validate.py` writes `network_report.md` and `network_map.png`.
- 300 s headless smoke run, an OpenDRIVE export check, and `gui-settings.xml` (edges coloured by NOx, vehicles by speed).
- `SUMO_API_NOTES.md` starts here and every flag is checked with `--help`.
- **G1:** all three networks validated, plus the documented `python -m nycemis gui` command.

**M2 Demand and calibration (Nov 16-17).**
- Enumerate the installed emission classes with a probe run per candidate and pick the `fleet.yaml` mix (about 85/10/5).
- `randomTrips.py` mirrors the Web Wizard's trip attributes, then `duarouter` builds explicit routes, with zero
  unroutable trips.
- Bisect the insertion rate on pilot seeds to hit mean-speed ratios of about 0.8, 0.6 and 0.45 under the validity limits.
- **G2:** `demand_levels.yaml` with evidence plots.

**M3 Harness, controllers, tests (Nov 18-19).**
- `runner.py`: libsumo, 1 s steps, run to completion with a 14,400 s cap, tripinfo with the emissions device and
  write-unfinished.
- An in-process logger reads edge and vehicle domain subscriptions, so per-step reads stay cheap.
- Each run writes `run.json`, parquet outputs and an atomic `DONE` marker; workers start with spawn.
- Controllers:
  - C0 `static` and C1 `tt_adaptive` (rerouting device, 60 s period).
  - C2 `random_reroute`, C3 `eco_reactive` and C4 `eco_ml` all go through `setEffort` on every non-internal edge plus
    `rerouteEffort`, with the effort guards of 4.3.
  - C5 `legacy_ml` (7.4).
  - C4 runs against a toy model until M5 freezes the real one.
- Tests 9.1-9.9, including the toy-network effort tests, reconciliation to 0.1%, determinism, libsumo vs TraCI,
  the poison test and the artifact demonstration.
- **G3:** green on smoke and on one Flushing run.

**M4 Pilot (Nov 20-21).**
- Pilot seeds 9000-9004 for C0, C1, C2 (η = 0.3), C3 (α = 0.5) and C5 at three levels. The legacy RF is trained on
  train seeds 0-1.
- Outputs: runtime per condition, the SD of paired Δ%, `power.py` (Wilcoxon and TOST at α = 0.05/12) giving n, the
  budget printout and the scope-cut ladder if needed.
- The legacy-metric vs matched-metric comparison completes the D1 and D2 audit with data.
- **G4:** n fixed, the α = 0 sanity check passing on Flushing, and `application/interim_note.md` (interim,
  non-confirmatory).

**M5 Forecaster and α\* (Nov 22-25).**
- The dataset runs use the mixed policies on train seeds. The `FeatureBuilder` (F1 and F2) is shared by data
  generation and live control.
- `edge_window` keeps edges with activity in windows k-2..k+1. Inactive edges are an explicit zero rule, and the
  share they hold is reported. This bounds the dataset at roughly 10-60M rows.
- Models: persistence, EMA, historical mean, Ridge and LightGBM, with 30-trial random search on validation seeds only.
- Then the triviality and leakage tests of the legacy task, and the α sweep for α\*_reactive and α\*_ml separately.
- The placebo η is matched to eco_ml's route-change rate, and the shadow-mode parity test is run.
- **G5:** forecast-skill report and tag `model-freeze-v1`.

**M6 Preregistration and confirmatory runs (Nov 26-29).**
- `PREREGISTRATION.md` follows Appendix B, including the analysis-code hash; tag `prereg-v1`.
- Run the test seeds 200 onwards for 6 conditions × 3 levels × n.
- **G6:** `experiment verify` clean.

**M7 Analysis (Nov 30).**
- The frozen stats (BCa, Wilcoxon, TOST, Holm over the 12 tests), figures, maps, road-class and Gini analysis, and
  `CLAIMS.md`.
- An independent adversarial review; every finding is fixed or logged in `DEVIATIONS.md`.
- **G7:** every PC reported, nulls included.

**M9 Paper and application (Dec 1-5).**
- `paper/main.tex`, with every number coming from generated `macros.tex`, and `refs.bib` with verified entries only.
- `make_arxiv_bundle.py`.
- `application/`: research summary of at most 450 words, claims ledger, FAQ and project page, plus `RESEARCH_AGENDA.md`.
- `verify-all`, then tag `v1.0`.

**M8 (Tier 2) and M10 (CARLA)** run only after G7 and their gates. M10 asks first before the multi-GB CARLA download.

## Compute budget (preliminary; the pilot replaces it)
- **Runs:** about 1,400-1,900 in total. That covers the dataset (288), the α sweep and references (about 470), the
  confirmatory runs (540-1,080 at n = 30-60), and the pilot and calibration (about 140).
- **Time:** at 3-10 min per run on 23 workers, roughly 4-14 h wall-clock, inside the 24 h budget.
- **Disk:** under 50 GB, mostly `edge_window`. A pre-batch check aborts if the expected use is over 50% of free space.

## Main risks and how they are handled
- **Per-step logging and control cost:** handled with subscriptions and batched predictions, profiled in the pilot.
  If too slow, the `edgeData` alternative in 6.6 is used, provided it agrees to 0.1%.
- **A Web Wizard option that doesn't exist in the installed SUMO:** checked with `--help` and recorded as a deviation.
- **Overpass refusing the request:** handled with tiles and mirrors. The osmium fallback was left unused.
- **libsumo failing to import on Windows:** the TraCI fallback is used and logged.
- **The 1.88 threshold or the legacy-replication cadence being too slow:** recorded as a deviation with the cadence
  actually used.
- **Calendar slip of more than 2 days at any gate:** the scope-cut ladder in section 8 applies, rung by rung.

## Verification
- **Every gate:** `pytest` (unit, integration, regression), `ruff`, the hygiene scan (no unfinished-work markers
  or absolute paths) and `experiment verify`.
- **End to end:** `python -m nycemis verify-all` covers all of section 9. Smoke also runs from a path with a space in it.
- **STATUS.md:** a ticked requirement list with evidence at each milestone, using the checklist in section 12.
- **Final check:** a clean-clone run of the README commands for `doctor` and `verify-all` (Definition of Done).
